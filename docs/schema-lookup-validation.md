# 授权表结构核实与完整版本收尾

## 实现

`catalog_schema` 已注册到统一 Tool Registry，受智能体绑定、工具启用状态及当前用户的 DISCOVER、QUERY_DATA 双权限控制。只返回已发布、非敏感字段及必要说明，不返回数据行。每次最多三张表、每张最多 80 个可见字段，总字段文本预算 15000 字符；超限明确提示，不假装返回了完整结构。

查询规划先核实 RAG 命中的候选表，替换重复的表/字段 RAG 文本，保留指标、关系与历史。模型可通过 `schema_request` 补查一次，再输出 SQL 或澄清问题，禁止无限补查。正常查询没有为 schema 再增加模型轮次。现有 SQL 预检、数据库权限与高风险审批保持不变。

旧数据查询 Agent 若已绑定 catalog_rag 和 readonly_sql，启动迁移时一次性绑定 catalog_schema；之后管理员移除绑定，重启不会再启用。未核实结构时不会执行 SQL。

结构来源是已发布的数据目录，不代表实时探测远端数据库；源结构漂移仍需目录同步及执行前校验。当前工具不含生产数据源的在线 introspection 适配。

## 必须纠正的历史结论

此前支付时间评测资料不一致：评测仓库没有 pay_date，但沿用了演示目录中的 pay_date 字段。因此不能将该题一概描述成模型凭空编造。此次仅修正隔离评测目录，使其字段与合成仓库一致，没有删改日常数据库/元数据。示例指纹随之重新验证，评测升级为 `2026-09-06.3-fixture-schema-consistency`。旧报告保留，不用不同版本报告声称准确率提升。

## 测试结果

- 隔离后端 226 项通过，前端现有测试 10 项通过，前端构建成功。
- `.data/evals/2026-09-06-schema-consistent-live.json`：真实模型六题全部通过。8 月 GMV=150、9 月追问=300、一对多订单去重=150；未授权域不查询；缺支付时间字段直接澄清、SQL 为空；问候不走 RAG。
- 此次问候首字约 1.39 秒。三道数据查询完整响应分别约 23.05、32.88、32.18 秒；缺字段澄清约 25.12 秒。正常查询为路由、规划、流式分析三次模型调用，没有额外 schema 规划轮次。
- 新日志/评测报告含每次模型调用节点、输入字符数（非 token 数）、成功状态、耗时，流式调用含首字耗时；不记录提示词或凭据。

这是一次六题样本，不能证明供应商不再超时或所有问题均正确。数据问答仍主要耗时在远端规划，不承诺固定百分比提速；未更换用户模型或放松准确性/权限约束。
