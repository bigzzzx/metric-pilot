# 数据目录审核与发布

管理员进入「数据目录 → 数据资产」，通过「待审核」及数据源筛选找到采集的草稿。打开草稿自动进入「审核编辑」；已有表和字段注释自动填入。

1. 核对业务名称、描述、别名、业务域、数仓层、数据粒度，以及字段说明、语义角色、敏感级别和样例脱敏方式。
2. 「保存草稿」仅保存编辑。「保存并发布」先保存，再检查表说明、数据粒度、字段说明，符合要求才发布。也可在列表的批量发布中勾选已核对的草稿，逐表返回结果。
3. 「退回」需填写原因，普通用户不可见；修改并保存后回到待审核。
4. 已发布资产的「发布管理」支持填写原因后撤回。撤回后可编辑并重新发布；普通用户及 RAG 即时失去该资产的可见性。关联只有两端都发布时才公开。

所有修改由后端校验管理权限，版本号避免覆盖他人编辑，审计日志保存编辑、发布、退回和撤回记录。发布和撤回后同步 Milvus 索引；向量服务失败时返回明确提示，下次检索重试。检索结果始终按当前发布状态与权限过滤。

重复采集保留已发布、已退回或人工审核保存的元数据，避免覆盖业务说明及脱敏配置；未审核草稿可刷新。已审核资产的源结构差异对比/版本合并尚未实现，目前会保留原版本。

删除数据源前必须撤回其全部已发布资产；删除仅清理连接配置和未发布目录记录，不删除远端数据库或业务数据。内置演示源不允许删除。

当前 PostgreSQL 接入提供元数据采集和发布检索。SQL 执行器仍针对内置 SQLite 演示仓，PostgreSQL 发布资产显示「仅可查看元数据」，不进入 SQLite 查询白名单，也不向 SQLite 请求远端样例。远端 SQL 执行需另行接入。

验证使用隔离 SQLite 与模拟索引故障，覆盖 HTTP 参数校验、权限、版本冲突、发布/退回/撤回、关联可见性、RAG 实时过滤及删除保护；不发布或修改用户现有 20 个 PostgreSQL 草稿。
