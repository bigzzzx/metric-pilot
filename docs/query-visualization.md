# 查询结果可视化

聊天分析现在支持指标卡、折线图、柱状图、横向条形图、环形图、散点图和分页数据表。结果区域可切换展示方式并导出图表 PNG；生成的图表规格和原始查询结果一起保存在会话中，刷新后恢复。手动下拉框切换只影响当前页面，刷新恢复该消息原始的图表配置。

示例：

- 查询 PostgreSQL 测试数仓 ods.orders 有多少行：默认指标卡。
- 查询 PostgreSQL 测试数仓 ods.orders 按 status 分组统计记录数，使用柱状图展示。
- 把刚才的柱状图改成环形图，使用相同的数据，不要重新查询：复用历史查询结果。
- 重新按 channel 分组统计 ods.orders 的记录数：重新规划并查询数据。

## 实现

路由模型同时查看当前问题、最近历史以及可信结果的字段类型，选择图表类型和字段。纯展示追问可跳过 RAG、SQL 规划、SQL 执行和分析模型；需要新字段、过滤、聚合或计算的请求仍走查询流程。普通查询不需要额外的图表模型调用：工具根据结果形状自动选择指标卡、趋势图或分类图。分析文字继续流式输出，图表随最终响应追加。

create_visualization 注册在现有 Tool Registry，绑定到 Data Analysis Agent，经过统一执行器的绑定检查及审计。工具参数仅包含当前结果 ID、图表类型、字段与标题。真实结果通过单次调用的 ContextVar 绑定，并验证用户、会话和结果 ID；模型不能通过工具参数填入任意数值。历史结果仅从后端生成的可信结果条目恢复，不将用户输入的 Tool result: 文本当作执行结果。

backend/visualization/ 分开管理输入输出结构、数据类型判断、工具和图节点。ChatResponse.visualizations 经由普通响应、流式完成响应、SQLite 会话持久化和完整回答缓存传递。前端 QueryVisualization 用按需加载的 ECharts 渲染，独立模块管理图表配置和样式。

## 展示边界

- 图表引用现有查询结果，不自行执行 SQL、补数或重新计算业务口径。默认最多绘制 500 行；分类图最多 50 项；超限保留分页数据表，提示先聚合。
- 重复横轴值不会被悄悄合计，提示按目标维度查询汇总结果。空值保留为空，折线不连接空值。
- 环形图只支持最多 8 项、单个非负数值字段及非零合计。分母明确为本次返回行合计，不能将 Top N、LIMIT 或部分数据误认为全量。
- 单位不从数字大小猜测；标题可由请求指定。不同单位的多个指标应分别查询或分别展示，当前不自动使用双轴。
- 导出图片带数据范围说明。执行依据中显示图表节点，纯换图明确显示“本轮未执行 SQL”。
- 此版本针对 SQL 查询结果；附件全文统计、堆叠图、透视表和收藏看板不包含在本次实现中。

## 验证

- test/test_visualization.py：类型选择、字段校验、占比边界、用户/会话隔离、工具绑定、持久化及换图跳过分析模型。
- test/visualization-options.test.mjs：日期排序、精确原始字符串保留、空值与轴映射。
- scripts/check_visualization.cjs：桌面与窄屏真实浏览器，图形渲染、切换、导出与刷新恢复（合成响应）。
- scripts/verify_visualization.py --username user1：使用当前模型及合成 PostgreSQL 数仓进行端到端验收；会创建一个可查看的验收会话。
