# 运行可靠性与索引恢复实施方案

日期：2026-11-06（北京时间）。基线 `01ea433`，在 `codex/runtime-reliability` 独立分支实施，不自动合并 main。

## 本轮范围

1. 生产运行保存执行快照、执行者身份和心跳；识别异常中断但不把超时等同回滚。
2. 业务数据与仓库提交凭证在同一事务提交，覆盖空结果；恢复使用同一仓库锁并撤销旧执行者资格，防止迟到进程再次写入。
3. 管理员核对后，仅对可靠的已提交结果补登资产、质量、血缘及缓存版本。已证实未提交的运行允许结束，但重新写入仍需新审批；连接、锁或凭证不明则继续阻塞。
4. Wiki/血缘索引任务持久化领取、租约、退避重试、死信及人工重试；重启后继续消费。所有目录向量写入共享跨进程串行锁，并在获锁后读取最新发布状态。
5. 管理界面显示恢复入口和索引积压/失败，不掩盖无法确认的状态。

不部署 Airflow/CDC，不新增任意 SQL 写入，不自动重放 ETL，不操作既有业务数据。统一 Ubuntu 部署及备份恢复属于下一阶段。

## 验收

- 使用临时平台库/仓库，在运行登记、数据提交、元数据登记等窗口中断进程，验证事务结果与恢复路径。
- 验证空结果提交、重复恢复、失去租约的旧执行者、并发恢复、凭证不符/仓库不可用、权限与新审批边界。
- 索引验证重复领取、崩溃回收、退避/次数上限、死信重试；恢复时不能让旧版本重新覆盖当前状态。
- 真实 Milvus 使用独立命名的验收集合，仅合成材料，验证发布、撤回、权限过滤和失败后追平；不清理既有集合。
- 后台完整回归、前端测试/构建、HTTP 闭环与实际数据库验收分层报告；不以合成用例通过率宣称生产准确率。
