# 聊天附件

点击聊天输入框的“＋”选择文件，也可拖放文件或粘贴图片。附件跟随当前会话保存，刷新或重启后仍可访问。未发送的附件可通过附件卡片上的 × 移除。

- 每条消息最多 5 个附件，每个最多 20 MB；每会话最多 30 个、每用户原始附件容量最多 200 MB。
- 文档沿用现有 PDF、DOCX、XLSX、PPTX、HTML、Markdown、文本和结构化文件解析器。扫描 PDF 仍需要 OCR 支持。
- 文档片段保存在项目 `.data/platform.db` 中，根据问题做本地词项匹配，提供最多约 18,000 字符的证据。较大文件只读取相关片段，不承诺对整份大型表格完成精确聚合计算。
- PNG、JPEG、WebP 会校验并压缩为不超过 2048 边长的 JPEG；下载与模型读取使用该标准化版本。
- 在“智能体管理”的“图片理解”区域标记支持视觉输入的已启用模型。目前图片调用支持 OpenAI 兼容接口（含 vLLM/Ollama 的兼容端点）。没有启用视觉模型时会保留图片并提示配置，不能以文本模型假装识图。

## 在聊天中导入知识库

例如：“将这个附件导入我的业务知识库”。Agent 确定文件和可写知识库后，在聊天中给出明确确认文本；回复“确认”执行，回复“取消”取消。一次确认对应一个文件和一个目标知识库，24 小时有效；切换话题会取消原待确认任务。

`import_attachment_to_knowledge` 工具通过统一工具执行器运行，验证用户、会话、附件归属、真实确认消息和知识库写权限，并记录工具审计。确认请求会被原子领取，重复确认不会重复导入。图片导入先由视觉模型转录为文本，再通过既有知识索引器解析并向量化。

未执行该工具时，附件不会进入长期向量知识库。含附件的会话跳过完整回答缓存，避免复用缺少附件上下文的旧答案。路由保留正常 SQL 和闲聊分支，后续附件问题由附件节点处理。

## 模块与验证

- `backend/attachments/`：存储、解析、问答和确认导入工具。
- `backend/api/attachments.py`：受用户认证保护的上传、下载、列表、删除与模型能力接口。
- `src/components/chat/ChatComposer.jsx`：上传、预览、粘贴和发送。
- `test/test_chat_attachments.py`：接口、会话隔离、文档问答、图片消息格式、确认、取消、权限变化和幂等验证。
- `scripts/check_chat_attachments.cjs`：使用合成接口的真实浏览器交互验证。
- `scripts/verify_chat_attachments.py --username <用户名>`：真实模型及知识索引验收，会创建一个合成测试会话和独立测试知识库。
