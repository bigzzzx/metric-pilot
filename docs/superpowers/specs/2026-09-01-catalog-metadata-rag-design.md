# 权限感知的数据目录元数据 RAG 设计

日期：2026-09-01  
状态：已确认，实施中

## 背景

数据目录中的表、字段、指标、术语和关联关系是 Data Agent 生成可靠 SQL 的依据，适合进入 RAG；真实数据行、样例中的敏感值和用户个人信息不进入该索引。此前代码同时保留静态 JSON 元数据和 SQLite 数据目录：关键词检索会按目录权限过滤，但静态元数据曾计划以共享向量写入通用知识库集合，无法按业务域或资产权限过滤。

## 决策

使用独立 Milvus 集合 `catalog_metadata_bge_small_zh_v1` 保存**已发布的语义元数据**，与下列数据隔离：

- 用户上传知识库：`knowledge_chunks_bge_small_zh_v1`
- 长期记忆：`user_memories_bge_small_zh_v1`
- 真实业务数据和样例数据：不写入向量库

每个元数据向量记录携带稳定 ID、实体类型、关联资产范围、业务域、内容版本和文本。目录发布器从 SQLite 的 `catalog_*` 表生成以下原子文档：

- 表/资产：描述、别名、数仓层级、粒度、主键及可公开给 Agent 的字段。
- 字段：数据类型、说明、别名、语义角色；`sensitive`/`restricted` 字段不进入 Agent RAG 文本。
- 指标与术语：定义、公式、SQL 口径、粒度、认证状态和别名。
- 关系：两端资产、Join 条件、基数、推荐 Join 方式；仅在两端资产均可见时供用户检索。

## 权限与检索流程

```text
目录发布 -> catalog_metadata 向量集合
用户提问 -> 可访问目录实体集合 -> 稠密检索 + 权限过滤
                                  -> 目录 BM25（同一权限集合）
                                  -> RRF 融合 -> rerank -> Agent prompt
```

权限判断复用数据目录的 `can_access(user_id, DISCOVER, ...)`。向量召回命中后会在 RRF 和 rerank 之前按资产/业务域重新校验；因此即使集合中保存了其他业务域的文档，其标题和内容也绝不会进入模型上下文。目录中的下线实体或过期版本在重新发布时删除。

## 发布与一致性

- 只有 `publish_status='published'` 的目录实体进入索引。
- 对全部发布文档计算内容哈希；未变化版本不重复嵌入。
- 内容变化时按稳定 ID upsert，已不再发布的记录从集合删除。
- SQLite 目录仍是事实来源；Milvus 只保存可重建的检索副本。
- 启动时和显式发布时均可执行幂等同步。

## 部署

远端 Ubuntu 的 Docker 已运行 Milvus、embedding 与 reranker，但三者只监听服务器 `127.0.0.1`。本地开发通过受控 SSH 隧道映射至 `127.0.0.1:19530/8081/8082`；生产环境应将应用服务与这些容器置于同一私网/Compose 网络，或使用受认证的内部地址，不能将服务匿名暴露到公网。

## 验收

1. 已发布目录元数据能写入独立集合并完成增量回填。
2. 表、指标和 Join 查询能同时走向量和 BM25，并在 Milvus/模型服务不可用时明确降级。
3. 无对应业务域权限的用户无法从任何 RAG 结果获取受限资产、字段或关系。
4. 用户上传知识库、长期记忆和数据目录元数据互不混入。
5. 变更、下线目录实体后，重新发布不会遗留可检索的旧内容。
