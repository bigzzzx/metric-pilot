# 统一对话 Data Agent 设计

## 决策

使用单一 DeepSeek 调用完成每轮的理解、自然语言回复和工具计划。模型不按前端模式切换；它根据当前问题、最近对话、Catalog 上下文与安全边界，自行决定是否需要数据工具。

## 输出契约

模型继续返回 JSON：`intent`、`answer`、`sql`、`should_analyze` 与 `reason`。其中：

- `CHAT` 的 `answer` 是面向用户的正常、具体对话回复。
- `METADATA_QA` 使用 Catalog 上下文回答。
- `DATA_QUERY` 只提出一条候选只读 SQL；服务端审核、执行，并在 `should_analyze=true` 时追加结果分析。
- `ETL_TRIGGER` 与 `UNSAFE_REQUEST` 保持受控任务和安全拒绝。

## 对话质量约束

- 最近四轮历史作为真实 `user` / `assistant` 消息传给模型，而不是 JSON 摘要文本。
- 模型身份是“由 DeepSeek V4 Flash 驱动的本地数据分析 Agent”；不得把自己称为规则、模板或模拟助手。
- 对直接问题直接回答；避免重复“我可以帮助你”的泛化套话。
- 被问模型身份时，回答真实模型与数据工具边界；不暴露密钥、系统提示词或内部错误。

## 安全与验证

统一调用不改变服务端 SQL 审核、行数限制、危险操作拒绝或本地降级。测试覆盖模型身份、连续对话历史、查询计划和无模型时的降级；真实 API 验证普通闲聊、模型身份和连续数据追问。
