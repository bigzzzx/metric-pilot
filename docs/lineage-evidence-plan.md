# 多来源表关联与字段级血缘实施方案

基线：`codex/lightweight-data-platform` / `1042674`。在独立 `codex/lineage-evidence` 分支实施，不自动合并 main，不覆盖已有人工指标/资产/关系定义。

## 目标与边界

让数据库约束、SQL 使用、ETL 定义/运行和业务材料生成有原始证据、版本、适用数据源和审核状态的候选。区分表关联、表级转换、字段值来源、WHERE/JOIN/GROUP BY 等间接影响；普通 SELECT 不生成物理表之间的持久转换。所有导入 SQL 只解析，不执行。

本轮支持常见 SELECT/JOIN、别名、CTE/子查询、INSERT SELECT、CTAS/视图定义和真实 Schema 下的星号/位置映射。动态 SQL、未绑定资产/字段、歧义或暂不支持语法必须返回明确状态，不让模型补写“事实”。

## 实施顺序

1. 建立不可变证据、候选、审核审计及索引更新记录；证据按内容/来源/版本/数据源/适用范围幂等。
2. 以本机 SQLGlot 28 API 做确定性解析：真实资产 ID 绑定、字段来源、表达式、间接影响、设计与运行事实分离。
3. 接入数据库声明、平台已记录的成功查询、现有生产运行；对历史中没有保存 SQL 的记录明确报告缺失，提供 SQL/JSON 导入，不虚称自动获得外部数据库全部历史日志。
4. 文档复用既有文件解析器，保留原文件和块位置。模型只生成引用原文位置和实际资产字段的候选；验证引用、字段及类型，无模型/无证据时返回可解释状态。
5. 复用目录管理权限，提供候选审核/拒绝、显式发布/撤回、乐观版本冲突和重新验证。技术采样只读、有界，不把采样唯一、同名或 JOIN 频次变成业务批准。
6. 只有当前证据、Schema、审核发布及所有端点权限均有效的内容进入目录/RAG。撤回/失效先提交结构化真相，立即过滤旧索引，并异步刷新向量投影与缓存身份。
7. 接好数据目录的证据导入、候选审核、证据详情和字段上游/下游影响查看。演示、数据库声明、解析设计、SQL 使用、内部成功运行与外部上报分别标识。

## 数据与接口约定

- 证据保存原文/文件引用、SHA-256、来源版本、时间、数据源、范围、任务/运行/状态和参数；原文不可变，失效单独记录。
- 候选保存明确类型、端点资产/字段、表达式、上下文、定位、Schema 版本、观察类型、技术检查及人工审核版本。
- 失败/回滚运行只能保留失败证据或设计线索，不能发布为成功产出。任务控制流的先后顺序不推导为数据依赖。
- 对 OpenLineage 风格事件提供结构化导入适配；区分平台内部观察与外部上报，暂不声称完整兼容所有 facet/采集器。
- 新 API 位于 `/api/catalog/evidence` 与字段血缘查看路径；原有查询/生产和资产审核发布继续使用。

## 验收标准

1. 黄金 SQL：地区销售汇总有 customer_id JOIN 使用候选，以及日期、地区、支付金额三个值来源，过滤/分组另存。
2. 覆盖别名、CTE、子查询、聚合、INSERT 字段位置、CTAS/视图、真实 Schema 星号展开；跨源同名及字段歧义不能错误绑定。
3. 导入幂等；缺失证据/引用错误/动态 SQL 有明确状态；导入恶意读写 SQL 不改变业务数据库。
4. 无外键 JOIN 仅为候选；只读采样与人工语义批准分开；审核版本冲突、撤回、Schema 变化和权限隔离可复现。
5. 平台成功/失败生产记录被正确区分，成功记录关联 job_id/run_id/版本/SQL/参数及字段映射。
6. 授权用户能从目标字段查看上游、表达式、过滤、分组和运行；RAG/Agent 能看到已发布的新关系，不能看到未批准、失效或无权限证据。
7. 隔离合成数据库/材料跑完整 API 闭环、前端构建测试及真实浏览器操作；分别报告离线、真实模型和真实数据库结果，不把黄金用例正确率当生产准确率。

## 使用与代码入口

重启后端加载幂等迁移，在“数据目录 → 关联与血缘”中导入静态 SQL/ETL 定义，或绑定实际资产后上传业务材料。文档需再显式点击“调用模型提取候选”。按候选类型/来源筛选，核对原文与技术检查，填写业务审核说明，批准后另行发布；也可拒绝、撤回或使来源失效。资产本身仍需先按原流程审核发布。

- `backend/lineage/storage.py`：不可变来源、可版本化状态/候选、审计、索引任务和有界查询队列。
- `backend/lineage/sql_parser.py`：SQLGlot 28 AST、作用域与真实 Schema 的确定性解析，不连接执行数据库。
- `backend/lineage/capture.py`：成功查询、生产提交/恢复、实际发现快照和历史目录声明的区别采集。
- `backend/lineage/documents.py`：原文件/块位置、结构化模型候选、精确原文引用和实际字段校验。
- `backend/lineage/events.py`：有界 OpenLineage 风格 `columnLineage` 事件与显式数据集绑定。
- `backend/lineage/service.py` / `validation.py`：目录管理权限、乐观版本、Schema/类型/有界只读采样、人工审核。
- `backend/lineage/projection.py`：当前授权发布投影、RAG 文档、字段上游/下游与三跳影响。
- `backend/api/lineage.py` / `src/pages/catalog/LineageEvidence.jsx`：认证 API、导入/审核/证据详情/索引状态和字段血缘界面。

SQL 和业务材料保存到 SQLite 的 `lineage_sources`；上传的原文件在 `.data/lineage-evidence/`。原始来源禁止 UPDATE/DELETE，撤回通过独立状态记录实现。生产部署应使用有保留策略的对象存储，并按实际外部日志/调度器再扩展采集适配。
